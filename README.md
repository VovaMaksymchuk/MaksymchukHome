# Home Dashboard — інвертор, батарея, графік світла

Мобільний дашборд для квартири. Home Assistant (локальний) **сам надсилає** дані у
Firebase Realtime Database через `rest_command`, а дашборд на Firebase Hosting
читає їх наживо. Відкривати порти чи робити HA доступним з інтернету не треба.

```
Anenji → EyeBond Local ┐
Svitlo Yeah / Yasno /  ├─ Home Assistant ──HTTPS PUT──▶ Firebase RTDB ◀── дашборд (Hosting, PWA)
DTEK (calendar)        ┘    (кожні 15 с)                   /home/...       Google-вхід
```

Що показує:
- **Світло є / немає** і скільки триває, коли увімкнуть за графіком, чи вистачить батареї до увімкнення
- **Батарея**: SOC, кВт·год, потужність заряду/розряду, час до 100% / до cut-off
- **Інвертор**: навантаження, % від 6.2 кВт, вихід, мережа, режим, температура, помилки
- **План vs факт** на вчора/сьогодні/завтра: прогнозні відключення з відкритих джерел і реальні (з датчика напруги)
- **Графіки за 24 год**: заряд і навантаження з підсвіткою періодів без світла
- **Статистика**: годин без світла сьогодні / за тиждень, найдовше, збіг з графіком, позапланові
- **Журнал**: кожне відключення, чи було за графіком, на скільки раніше/пізніше

Демо без жодних налаштувань: `python3 -m http.server -d public 8080` → <http://localhost:8080/?demo>

## 1. Firebase (≈10 хв, безкоштовний план Spark)

1. <https://console.firebase.google.com> → **Add project**.
2. **Build → Realtime Database → Create database** → регіон `europe-west1` → locked mode.
3. **Build → Authentication → Get started** → увімкни **Google**, **Email/Password** (для HA) і **Anonymous** (для входу за паролем).
4. **Authentication → Users → Add user** — це «користувач» для HA, напр. `ha@home.local`
   + довгий випадковий пароль. Скопіюй його **User UID**.
5. **Realtime Database → Data** — додай вручну (кнопка «+»):
   ```
   access
     writers
       <UID користувача HA>: true
   ```
6. **Project settings → General → Your apps → Web (</>)** → зареєструй застосунок, скопіюй
   `firebaseConfig` у [`public/config.js`](public/config.js). `databaseURL` — адреса бази з кроку 2.
7. У [`.firebaserc`](.firebaserc) впиши ID проєкту.
8. Деплой (правила бази + хостинг):
   ```bash
   npm i -g firebase-tools
   firebase login
   firebase deploy
   ```
   Сайт буде на `https://<project>.web.app`.
9. **Вхід через Google:** відкрий сайт, натисни «Увійти через Google» → побачиш екран
   «Немає доступу» з твоїм UID → додай у базу `access/viewers/<твій UID>: true`.
10. **Вхід за простим паролем:** порахуй хеш і додай його в базу як `pin/hash`:
    ```bash
    ./tools/pin_hash.sh <projectId> <пароль>
    ```
    Пароль ніде не зберігається у відкритому вигляді — лише SHA-256 від `projectId:пароль`.

### Як працює вхід за паролем

- Пароль вводиться один раз — пристрій пам'ятає вхід, доки не натиснеш «Вийти».
- **3 невірні спроби → блокування 1 хв**, далі кожне наступне блокування вдвічі довше:
  2, 4, 8 хв … до 24 год. Лічильник обнуляється лише після правильного пароля
  (або кількість спроб — після години без спроб; тривалість блокування — ні).
- Обмеження перевіряє **сервер** (правила бази, `pin_guard`), а не браузер: кожна перевірка
  пароля можлива лише разом із записом «-1 спроба», тож обійти ліміт через API не вийде.
  Лічильник спільний для всіх пристроїв.
- Хтось чужий може навмисно «зажати» вхід за паролем блокуванням — тоді входь через Google;
  уже залогінені пристрої працюють далі.
- **Змінив пароль** (новий `pin/hash`) → усі пристрої, що входили за старим паролем,
  автоматично повертаються на екран входу.
- Раджу 6+ цифр: навіть з блокуваннями 4 цифри — це лише 10 000 варіантів.
- Клавіатура: у `config.js` → `pinKeyboard: "numeric"` (цифри) або `"text"` (літери).
- Подивитись екран входу без Firebase: `/?demo=login`, пароль `1234`.

> Порада для iPhone: у `config.js` постав `authDomain: "<project>.web.app"` — тоді вхід через
> Google працює і в режимі «на початковий екран».

Перевірити запис без HA: `tools/test_push.sh` (інструкція всередині).

Правила бази можна перевірити в **Realtime Database → Rules → Rules Playground**
(напр. запис у `pin_try/<uid>` без зміни `pin_guard` має бути відхилений).

## 2. Home Assistant

1. **Графік відключень.** Встанови через HACS одну з інтеграцій, що дає `calendar.*`:
   - [Svitlo Yeah](https://github.com/ALERTua/ha-svitlo-yeah) — багато областей (Київ, Дніпро, Одеса, Хмельницький, Івано-Франківськ, Ужгород…)
   - [Yasno Outages](https://github.com/denysdovhan/ha-yasno-outages) — Київ, Дніпро
   - [DTEK](https://github.com/aavdberg/ha-dtek) — Київ, Київщина, Дніпро, Одеса

   Обери свою чергу/адресу, запам'ятай `entity_id` календаря.
2. У `configuration.yaml`:
   ```yaml
   homeassistant:
     packages: !include_dir_named packages
   ```
3. Скопіюй [`homeassistant/packages/home_dashboard.yaml`](homeassistant/packages/home_dashboard.yaml)
   у `/config/packages/` і пройдись по позначках **⚙️**:
   - ⚙️1 `YOUR-DB-URL` — адреса бази (без `https://`), 2 місця (вже підставлено для `maksymchukhome`)
   - ⚙️2 `entity_id` сенсорів інвертора від EyeBond Local (Settings → Devices → інвертор).
     Назви в пакеті — орієнтовні `sensor.anenji_*`, у тебе можуть відрізнятись.
     Чого немає — залиш, буде «—». (2 місця — скрипт `push_live` і автоматизація `history`)
   - ⚙️3 сенсор напруги мережі для `binary_sensor.grid_power` (поріг 170 В)
   - ⚙️4 календар графіка (2 місця) — встанови через HACS одну з інтеграцій, що дає
     `calendar.*` (DTEK KREM Outages, Svitlo Yeah, Yasno Outages — див. вище), запам'ятай
     `entity_id`
   - ⚙️5 *(опційно)* окремий лічильник споживання всієї квартири (не інвертора) — якщо
     з'явиться апаратно (напр. Zigbee/Tuya на вводі). Без нього поле `apt` просто не
     пишеться, і картки «Дім»/«Місто» на вкладці «Стан» покажуть «—»
4. Додай рядки з [`homeassistant/secrets.example.yaml`](homeassistant/secrets.example.yaml) у `/config/secrets.yaml`.
5. **Developer tools → Check configuration** → Restart.
6. Перевір: `sensor.firebase_token` = `ok`. Якщо `error` — дивись атрибут `http_status`
   (400 — неправильний email/пароль або вимкнений Email/Password провайдер).

> Знак струму батареї: дашборд вважає «+» = заряд. Якщо показує навпаки — постав
> `bat_sign: -1` у скрипті і в автоматизації історії.

### 2.1 Розумний будинок — вимикачі, опалення, датчики (вкладки «Стан»/«Світло»)

Окремий пакет, працює незалежно від кроків 1–3 вище (інвертора/графіка може не бути).

1. Скопіюй [`homeassistant/packages/smart_home.yaml`](homeassistant/packages/smart_home.yaml)
   у `/config/packages/` поруч із `home_dashboard.yaml` — обидва вантажаться як один пакет,
   `rest_command.firebase_put`/`firebase_delete`/`sensor.firebase_token` з кроку 1 переюзаються,
   повторно їх визначати не треба.
2. Заміни `switch.YOUR_*` / `climate.YOUR_*` / `binary_sensor.YOUR_*` на реальні `entity_id`
   своїх Tuya-пристроїв (Settings → Devices & services → Tuya). Кожен список **повторюється
   у двох місцях** файлу (пуш стану + виконання команд) — онови скрізь:
   - вимикачі світла: Вітальня / Спальня / Кабінет / Коридор (`smart_home_push_switches`,
     `smart_home_commands`)
   - опалення: Котел / Тепла підлога — climate-сутності з `current_temperature`/`temperature`
     (`smart_home_push_climate`, `smart_home_commands`)
   - датчики: протікання (Ванна, Кухня), дим (Кухня, Коридор) — `smart_home_push_sensors`
3. Назви кімнат/сенсорів і їхній список редагуються в [`public/config.js`](public/config.js)
   (`rooms`, `climateDevices`, `sensorGroups`) — якщо додаєш/перейменовуєш кімнату, онови
   і там, і в `smart_home.yaml` (ключі зліва, напр. `living`, мають збігатись).
4. Нічого додатково в Firebase налаштовувати не треба — дашборд (переглядач) уже має право
   писати в `home/commands/*`, а HA читає цей шлях раз на 3 с, виконує дію через Tuya і сам
   видаляє запис.
5. Restart → перевір на дашборді (без `?demo`): перемикання вимикача чи кнопка +/− на
   опаленні має відобразитись у HA (Developer Tools → States на відповідній сутності)
   протягом ~3 с, а потім підтверджений стан повернеться назад на дашборд.

## Що де лежить у базі

| Шлях | Хто пише | Що |
|---|---|---|
| `home/live` | HA, кожні 15 с + при зміні світла | поточний стан, `ts` = час сервера Firebase |
| `home/grid_events/<unix sec>` | HA, при зміні | `{on: true/false}` — з цього рахуються відключення |
| `home/history/<YYYY-MM-DD>/<unix sec>` | HA, кожні 5 хв | `soc, load, bp, g` для графіків; >45 днів видаляється |
| `home/schedule/latest` | HA, кожні 10 хв | події календаря вчора…+2 дні |
| `home/schedule/days/<YYYY-MM-DD>` | HA | знімок плану на день — для «план vs факт» у минулому |
| `home/switches/<roomId>` | HA, кожні 10 с | стан вимикача світла (`on`) |
| `home/climate/<id>` | HA, кожні 10 с | опалення: `current`, `target`, `mode` |
| `home/sensors/leak/<id>`, `home/sensors/smoke/<id>` | HA, кожні 10 с | `alarm: true/false` |
| `home/commands/switches/<roomId>`, `home/commands/climate/<id>` | дашборд (переглядач!) | команда для HA; HA виконує й сам видаляє запис (раз на 3 с) |
| `access/writers`, `access/viewers` | ти вручну | хто може писати / читати (Google-акаунти) |
| `pin/hash` | ти вручну | SHA-256 пароля; ніхто не може його прочитати |
| `pin_guard` | дашборд | лічильник невдалих спроб і блокування (контролюють правила) |
| `pin_try/<uid>` | дашборд | хеш, введений на конкретному пристрої |

Обсяг: ~30 КБ історії на день, тобто кілька МБ на рік — далеко в межах безкоштовного плану
(1 ГБ зберігання, 10 ГБ трафіку/міс).

## Нюанси

- **Навантаження при світлі ≈ 0.** Через АВР квартира живиться напряму від мережі, інвертор
  бачить лише заряд батареї. Справжнє споживання квартири видно тільки під час відключення.
  Якщо захочеш бачити його завжди — потрібен окремий лічильник (напр. Zigbee/Tuya на вводі).
- **Роутер і Raspberry Pi** мають бути на інверторі, інакше під час відключення дані не підуть.
  Якщо HA мовчить довше 2 хв, дашборд показує банер «офлайн» і останній відомий стан.
- **Безпека.** HA-користувач може тільки писати в `/home`, нічого не читає. Переглядачі
  (Google або пароль) — лише читають, за одним винятком: пишуть у `home/commands/*`
  (вимикачі світла, уставка опалення) — HA сам читає цей шлях і виконує дію, тож ніхто
  інший не отримує прямого доступу до Tuya. Пароль HA-користувача — лише у `secrets.yaml`.
- **Точність «факту»** — ±10 с (фільтр коротких провалів у `binary_sensor`).
